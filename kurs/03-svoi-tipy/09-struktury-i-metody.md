# 9. Структуры, методы и блок `impl`

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

До сих пор мы пользовались готовыми типами. Пора создавать свои. Структура объединяет связанные данные под одним именем и даёт им смысл: не безымянный кортеж `(u32, u32)`, а `Rectangle` с полями `width` и `height`. А блок `impl` добавляет к данным поведение.

## Определение и создание

```rust
struct User {
    name: String,
    email: String,
    active: bool,
}

fn main() {
    let user = User {
        name: String::from("Алия"),
        email: String::from("a@b.kz"),
        active: true,
    };
    println!("{}", user.name);
}
```

Имена структур пишут в `CamelCase`, поля — в `snake_case`. Порядок полей при создании значения не важен: они называются явно.

Чтобы менять поля, изменяемой объявляют **всю структуру** — отдельного изменяемого поля в Rust нет:

```rust
let mut user = User { /* ... */ };
user.active = false;
```

Обратите внимание на типы полей: `String`, а не `&str`. Структура **владеет** своими данными — тогда её содержимое живёт ровно столько же, сколько она сама. Хранить в полях ссылки можно, но это требует времён жизни (статья 18), и на старте так делать не стоит.

Два сокращения, которые пригодятся сразу.

**Сокращённая инициализация полей** — если переменная называется так же, как поле, повторяться не нужно:

```rust
fn build_user(name: String, email: String) -> User {
    User { name, email, active: true }     // вместо name: name, email: email
}
```

**Синтаксис обновления структуры** — взять остальные поля из другого значения:

```rust
let u2 = User {
    email: String::from("c@d.kz"),
    ..u1
};
```

Здесь важная деталь про владение: `..u1` **перемещает** поля, которые не были указаны явно. Поле `name` — это `String`, оно переехало в `u2`, и `u1` целиком использовать больше нельзя. Если бы все поля были `Copy`-типами, `u1` остался бы годен.

## Кортежные структуры

Иногда имена полей избыточны, но тип нужен свой:

```rust
struct Meters(f64);
struct Point(i32, i32);

let distance = Meters(5.5);
println!("{}", distance.0);
```

Поля здесь безымянные, доступ по индексу. Главная польза — **типобезопасность**: функция, принимающая `Meters`, не примет `f64` или `Feet`, хотя внутри это одно и то же число. Дешёвый способ поймать целый класс ошибок.

## Методы

Поведение добавляется в блоке `impl`:

```rust
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}

let r = Rectangle { width: 3, height: 4 };
println!("{}", r.area());     // 12
```

Первый параметр метода — всегда `self`, и от его формы зависит, что метод может делать. Вариантов три:

- **`&self`** — заимствует структуру. Метод только читает данные; это большинство случаев.
- **`&mut self`** — заимствует с правом менять. Метод изменяет поля.
- **`self`** — **забирает владение**. Метод преобразует значение в другое, «поглощая» исходное.

```rust
impl Rectangle {
    fn scale(&mut self, k: u32) {
        self.width *= k;
        self.height *= k;
    }

    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}
```

Правила владения здесь ровно те же, что в статьях 6–7: `&self` — неизменяемое заимствование, `&mut self` — изменяемое, и вызвать его можно только у `mut`-переменной. Форма `self` встречается редко и всегда осознанно.

## Ассоциированные функции

Функция в блоке `impl` **без** `self` — не метод, а ассоциированная функция. Вызывается через двойное двоеточие:

```rust
impl Rectangle {
    fn new(width: u32, height: u32) -> Self {
        Self { width, height }
    }

    fn square(size: u32) -> Self {
        Self { width: size, height: size }
    }
}

let r = Rectangle::new(3, 4);
let s = Rectangle::square(5);
```

`Self` с большой буквы — псевдоним типа, внутри которого мы находимся. Пишут его вместо `Rectangle`, чтобы при переименовании структуры не править весь блок.

Именно так устроены конструкторы: в Rust нет специального синтаксиса для них, есть соглашение называть такую функцию `new`. Знакомый `String::from` — ровно такая же ассоциированная функция.

## Печать структуры

Попробуем вывести структуру целиком:

```rust
// ❌ не компилируется
println!("{p:?}");
```

```
error[E0277]: `P` doesn't implement `Debug`
  |
  = note: add `#[derive(Debug)]` to `P` or manually `impl Debug for P`
help: consider annotating `P` with `#[derive(Debug)]`
  |
1 + #[derive(Debug)]
```

Rust не печатает произвольные типы «как-нибудь»: способ вывода нужно выбрать явно. Самый простой — попросить компилятор сгенерировать его автоматически:

```rust
#[derive(Debug)]
struct Rectangle { width: u32, height: u32 }

println!("{r:?}");      // Rectangle { width: 6, height: 8 }
println!("{r:#?}");     // то же самое, но многострочно
```

`#[derive(...)]` — атрибут, генерирующий реализацию за вас. `Debug` — отладочный вывод, его добавляют почти всем структурам. Подробнее про derive и другие трейты — в статье 17.

## Что запомнить

- Структура объединяет связанные данные и владеет ими; поля обычно объявляют владеющими типами (`String`, а не `&str`).
- Изменяемой объявляется вся структура целиком, не отдельное поле.
- Сокращение `User { name, email }` работает, когда переменные названы как поля.
- Синтаксис `..other` дополняет структуру и **перемещает** неуказанные поля.
- Кортежные структуры дают типобезопасность без имён полей.
- Первый параметр метода: `&self` — читать, `&mut self` — менять, `self` — забрать владение.
- Функция в `impl` без `self` — ассоциированная, вызывается через `Type::name()`; так делают конструкторы `new`.
- Для печати структуры нужен `#[derive(Debug)]` и формат `{:?}` или `{:#?}`.

## Практика

**1. Своя структура.** Опишите структуру `Book` с полями «название», «автор», «год» и «прочитана». Создайте значение, поменяйте флаг прочтения, выведите структуру целиком в многострочном формате. Готово, когда вывод читается как список полей.

**2. Конструктор.** Добавьте `Book::new(title, author, year)`, который создаёт книгу с `read: false`. Используйте `Self` и сокращённую инициализацию. Готово, когда создание книги занимает одну строку.

**3. Три формы `self`.** Добавьте три метода: `description(&self) -> String`, `mark_read(&mut self)` и `into_title(self) -> String` (возвращает название, поглощая книгу). Вызовите все три и объясните, почему после третьего книга недоступна. Готово, когда компилятор подтвердил ваше объяснение ошибкой.

**4. Типобезопасность.** Опишите кортежные структуры `Celsius(f64)` и `Fahrenheit(f64)` и функцию перевода из первой во вторую. Попробуйте передать в неё `Fahrenheit` и запишите ошибку. Готово, когда компилятор отказался путать градусы.

**5. Владение при обновлении.** Создайте структуру с полем `String`, сделайте из неё вторую через `..first`, а затем попробуйте использовать `first`. Разберите ошибку. Затем измените структуру так, чтобы такой код компилировался. Готово, когда понимаете, какое свойство полей это меняет.
