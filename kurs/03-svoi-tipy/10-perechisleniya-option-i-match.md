# 10. Перечисления, `Option<T>`, `match` и `if let`

> ⏱ **~55 минут** · теория 20 мин · практика 35 мин

Структура из прошлой статьи говорит «и то, **и** это»: у прямоугольника есть и ширина, и высота. Перечисление говорит «либо то, **либо** это»: фигура — либо круг, либо прямоугольник, либо точка. Вместе с сопоставлением с образцом это даёт Rust его выразительность — и заодно избавляет язык от `null`.

## Перечисления с данными

Простое перечисление выглядит привычно:

```rust
enum Direction {
    North,
    South,
    East,
    West,
}
```

Но настоящая сила в том, что каждый вариант может **нести собственные данные**, причём разного вида:

```rust
#[derive(Debug)]
enum Shape {
    Circle(f64),                // как кортежная структура
    Rect { w: f64, h: f64 },    // как обычная структура
    Point,                      // без данных
}
```

В большинстве языков для такого пришлось бы городить иерархию классов. Здесь — один тип с тремя формами. Значение типа `Shape` — это ровно один из вариантов, и компилятор об этом знает.

Как и структурам, перечислениям можно добавлять методы через `impl`.

## `match`

`match` сравнивает значение с образцами и выполняет подходящую ветвь. При этом он **вытаскивает данные** из варианта:

```rust
impl Shape {
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(r) => 3.14159 * r * r,
            Shape::Rect { w, h } => w * h,
            Shape::Point => 0.0,
        }
    }
}
```

Имена `r`, `w`, `h` не объявлены заранее — они появляются при разборе образца и доступны в правой части ветви.

Главное свойство `match` — **исчерпывающесть**. Забыть вариант нельзя:

```rust
// ❌ не компилируется
match e {
    E::A => println!("a"),
    E::B => println!("b"),
}
```

```
error[E0004]: non-exhaustive patterns: `E::C` not covered
 --> ne.rs:4:11
  |
4 |     match e {
  |           ^ pattern `E::C` not covered
```

Это одна из самых полезных вещей в языке. Добавили в перечисление новый вариант — компилятор перечислит все места, где его надо обработать. В языке с `switch` вы узнали бы об этом от пользователей.

Для «всех остальных случаев» есть два образца: `_` — просто пропустить, или имя переменной — если значение нужно.

`match` — выражение, поэтому его результат можно присвоить. Все ветви обязаны возвращать один тип.

## `Option<T>` вместо `null`

Теперь самое важное применение перечислений. В Rust нет `null` — вместо него стандартный тип:

```rust
enum Option<T> {
    Some(T),
    None,
}
```

`T` здесь — любой тип (обобщения разберём в статье 15). `Option<i32>` — «либо число, либо ничего».

Почему это лучше `null`? Потому что **отсутствие значения становится видно в типе**. `i32` — всегда число, гарантированно. `Option<i32>` — может быть пусто, и компилятор заставит это обработать:

```rust
// ❌ не компилируется
let x: i8 = 5;
let y: Option<i8> = Some(5);
let s = x + y;
```

```
error[E0277]: cannot add `Option<i8>` to `i8`
  |
4 |     let s = x + y;
  |               ^ no implementation for `i8 + Option<i8>`
```

Сложить их нельзя, пока вы не решите, что делать с пустым случаем. Именно так Rust закрывает «ошибку на миллиард долларов» — обращение к `null`, которое в других языках падает в рантайме.

Разбирается `Option` тем же `match`:

```rust
fn describe(n: Option<i32>) -> String {
    match n {
        Some(0) => String::from("ноль"),
        Some(x) if x < 0 => format!("отрицательное {x}"),
        Some(x) => format!("положительное {x}"),
        None => String::from("ничего"),
    }
}
```

Здесь видны две дополнительные возможности: **образец с конкретным значением** (`Some(0)`) и **страж** — условие `if x < 0` после образца. Ветви проверяются сверху вниз, поэтому частные случаи ставят первыми.

Макрос `format!` работает как `println!`, но возвращает `String`, а не печатает.

## `if let` и `let else`

Когда интересен один вариант из многих, `match` избыточен:

```rust
match config {
    Some(v) => println!("{v}"),
    None => {}
}
```

Короче так:

```rust
if let Some(v) = config {
    println!("if let: {v}");
}
```

`if let` — это `match` с одной ветвью. К нему можно добавить `else`.

Обратная ситуация: значение обязано быть, а иначе работать дальше бессмысленно. Для этого есть `let else`:

```rust
let Some(v) = config else {
    panic!("нет значения");
};
println!("let else: {v}");
```

Если образец не совпал, выполняется блок `else`, который **обязан прервать выполнение** — через `return`, `break` или панику. Зато после этой строки `v` доступна как обычная переменная, без вложенности. Приём избавляет от «лестницы» из вложенных `if let` и очень популярен в реальном коде.

## Полезные методы `Option`

Разбирать `match` вручную каждый раз не нужно — у `Option` десятки готовых методов:

```rust
let v = None::<u8>.unwrap_or(42);         // 42 — значение по умолчанию
```

Стоит запомнить сразу: `unwrap_or(default)`, `unwrap_or_default()`, `map(f)` — преобразовать содержимое, `is_some()` / `is_none()` — проверить.

Отдельно про `unwrap()` и `expect("...")`: они достают значение, **паникуя** на `None`. В учебном коде это нормально, в рабочем — только там, где вы можете доказать, что `None` невозможен. Подробно — в статье 13.

## Что запомнить

- Перечисление описывает выбор «либо-либо», и каждый вариант может нести свои данные.
- `match` разбирает значение по образцам и одновременно извлекает данные из вариантов.
- `match` исчерпывающий: пропущенный вариант — ошибка компиляции `E0004`. Это защита при добавлении новых вариантов.
- Образцы могут быть конкретными значениями и иметь стражей `if условие`; проверяются сверху вниз.
- `null` в Rust нет; отсутствие значения выражается типом `Option<T>` и потому видно в сигнатурах.
- `if let` — короткая форма для одного варианта, `let else` — для «иначе выходим», без вложенности.
- `unwrap()` паникует на `None` — в рабочем коде предпочитают `unwrap_or` и `match`.

## Практика

**1. Своё перечисление.** Опишите `Command` с вариантами `Quit`, `Move { x: i32, y: i32 }`, `Write(String)` и `ChangeColor(u8, u8, u8)`. Напишите функцию, которая через `match` печатает описание любой команды. Готово, когда обработаны все четыре варианта без `_`.

**2. Исчерпывающесть на практике.** Добавьте в перечисление пятый вариант, **не** трогая функцию. Запустите сборку и прочитайте ошибку. Готово, когда понимаете, почему это свойство ценно при рефакторинге.

**3. Option вместо null.** Напишите функцию `find_first_even(numbers: &[i32]) -> Option<i32>`, возвращающую первое чётное число или `None`. Обработайте оба случая у вызывающей стороны через `match`. Готово, когда программа корректно отрабатывает и на массиве без чётных.

**4. Три способа разбора.** Разберите один и тот же `Option` тремя способами: `match`, `if let`, `unwrap_or`. Сравните, сколько строк занял каждый. Готово, когда можете сказать, в какой ситуации какой уместен.

**5. `let else` и стражи.** Напишите функцию, которая принимает `Option<i32>`, через `let else` выходит при `None`, а затем через `match` со стражами печатает «отрицательное», «ноль», «маленькое» (до 100) или «большое». Готово, когда все четыре ветви достижимы и проверены.
