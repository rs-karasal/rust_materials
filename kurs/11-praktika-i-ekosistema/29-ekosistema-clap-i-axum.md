# 29. Экосистема: CLI на `clap`, веб на `axum`

> ⏱ **~55 минут** · теория 20 мин · практика 35 мин

Язык вы уже знаете. Осталось увидеть, как на нём делают две самые частые вещи: утилиту командной строки и HTTP-сервис. Обе задачи решаются крейтами, которые устроены одинаково — они превращают ваши структуры в интерфейс. Это и есть характерный стиль экосистемы Rust: описываете данные, поведение выводится из типов.

## CLI на `clap`

```toml
clap = { version = "4", features = ["derive"] }
```

Аргументы командной строки описываются структурой:

```rust
use clap::{Parser, Subcommand};

#[derive(Parser)]
#[command(name = "tasks", version, about = "Менеджер задач")]
struct Cli {
    #[arg(short, long, default_value = "tasks.json")]
    file: String,

    #[arg(short, long)]
    verbose: bool,

    #[command(subcommand)]
    command: Command,
}

#[derive(Subcommand)]
enum Command {
    Add { title: String },
    List {
        #[arg(long)]
        done: bool,
    },
}
```

Разбор — одна строка, дальше работаете с обычной структурой:

```rust
let cli = Cli::parse();

match cli.command {
    Command::Add { title } => println!("добавлено: {title}"),
    Command::List { done } => println!("список, выполненные: {done}"),
}
```

Обратите внимание: подкоманды — это перечисление, и `match` по нему исчерпывающий. Добавите подкоманду — компилятор напомнит её обработать.

Справку `clap` генерирует сам:

```
Менеджер задач

Usage: tasks [OPTIONS] <COMMAND>

Commands:
  add
  list
  help  Print this message or the help of the given subcommand(s)

Options:
  -f, --file <FILE>  [default: tasks.json]
  -v, --verbose
  -h, --help         Print help
  -V, --version      Print version
```

И сам же обрабатывает ошибки ввода:

```
error: unexpected argument '--nope' found

Usage: tasks list [OPTIONS]

For more information, try '--help'.
```

Ничего из этого писать не пришлось. `short` и `long` дают `-f` и `--file`, `default_value` — значение по умолчанию, `bool` автоматически становится флагом. Версия и описание берутся из `Cargo.toml` по ключевому слову `version`.

## Веб-сервис на `axum`

```toml
axum = "0.8"
tokio = { version = "1", features = ["full"] }
serde = { version = "1", features = ["derive"] }
```

`axum` построен на tokio, поэтому всё из статей 26–27 применимо напрямую. Обработчик — обычная асинхронная функция:

```rust
async fn health() -> &'static str {
    "ok"
}
```

Маршруты собираются в роутер:

```rust
let app = Router::new()
    .route("/health", get(health))
    .route("/tasks/{id}", get(get_task))
    .route("/tasks", post(create));

let listener = tokio::net::TcpListener::bind("127.0.0.1:3000").await.unwrap();
axum::serve(listener, app).await.unwrap();
```

## Экстракторы

Главная идея `axum`: **что функция принимает, то и извлекается из запроса**.

```rust
async fn get_task(Path(id): Path<u32>) -> Json<Task> {
    Json(Task { id, title: String::from("пример") })
}

async fn create(Json(payload): Json<NewTask>) -> Json<Task> {
    Json(Task { id: 1, title: payload.title })
}
```

`Path<u32>` вытаскивает часть URL и **превращает в число** — не строка, а `u32`. Придёт `/tasks/abc` — клиент получит 400, обработчик даже не вызовется. `Json<NewTask>` разбирает тело запроса в структуру через `serde` из прошлой статьи; невалидный JSON тоже отсеивается до вашего кода.

Проверим:

```
health -> ok
get -> {"id":42,"title":"пример"}
post -> {"id":1,"title":"новая"}
```

Сигнатура функции описала контракт эндпоинта целиком, а валидация оказалась следствием типов. Есть и другие экстракторы: `Query<T>` для параметров строки запроса, `State<T>` для общего состояния (то самое `Arc<Mutex<T>>` из статьи 25), `HeaderMap` для заголовков.

## Ориентиры в экосистеме

Крейтов много, и знание нескольких опорных экономит время:

| Задача | Крейт |
|---|---|
| CLI | `clap` |
| HTTP-сервер | `axum`, `actix-web` |
| HTTP-клиент | `reqwest` |
| База данных | `sqlx` (SQL с проверкой запросов при компиляции), `diesel` (ORM) |
| Логирование | `tracing` (для асинхронного кода), `log` + `env_logger` |
| Дата и время | `chrono`, `time` |
| Регулярные выражения | `regex` |
| Случайные числа | `rand` |
| Тестирование | `proptest`, `criterion` (бенчмарки) |

Отдельного упоминания заслуживает `sqlx`: макрос `query!` проверяет SQL **на этапе компиляции**, обращаясь к настоящей базе. Опечатка в имени столбца ломает сборку, а не прод. Тот же принцип, что у экстракторов и `serde`: ошибку ловят как можно раньше.

Выбирая крейт, смотрите на: дату последнего релиза, число зависимых крейтов на crates.io, наличие документации на docs.rs. Экосистема Rust моложе, чем у Java или Python, — популярный крейт всегда лучше идеально подходящего, но заброшенного.

## Что запомнить

- Характерный приём экосистемы: интерфейс описывается структурой, поведение выводится из типов.
- `clap` строит разбор аргументов, справку и обработку ошибок из `#[derive(Parser)]`.
- Подкоманды — перечисление, поэтому `match` по ним исчерпывающий.
- `axum` работает поверх tokio; обработчик — обычная `async fn`.
- Экстракторы (`Path`, `Json`, `Query`, `State`) достают данные из запроса и валидируют их **до** вызова обработчика.
- Ошибка типа в запросе превращается в 400 автоматически.
- `sqlx` проверяет SQL при компиляции — тот же принцип раннего обнаружения ошибок.
- При выборе крейта смотрите на активность и число зависимых проектов.

## Практика

**1. Первая утилита.** Напишите CLI, принимающий путь к файлу и флаг `--count`, и печатающий либо содержимое, либо число строк. Готово, когда `--help` показывает осмысленную справку, которую вы не писали.

**2. Подкоманды.** Расширьте утилиту подкомандами `add`, `list`, `done` с их аргументами. Готово, когда `match` по подкомандам исчерпывающий и справка сгенерирована для каждой.

**3. Первый эндпоинт.** Поднимите сервер с `GET /ping`, отвечающим `pong`. Проверьте через `curl`. Готово, когда сервер отвечает на запрос.

**4. Экстракторы.** Добавьте `GET /users/{id}`, возвращающий JSON, и `POST /users`, принимающий JSON. Отправьте в первый нечисловой id, во второй — сломанный JSON. Готово, когда оба случая дают 400 без вашего кода проверки.

**5. Общее состояние.** Добавьте в сервер список задач в памяти через `State<Arc<Mutex<Vec<Task>>>>`. Реализуйте добавление и получение списка. Готово, когда добавленная задача видна следующим запросом.
