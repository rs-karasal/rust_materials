# 15. Обобщённые типы (generics)

> ⏱ **~45 минут** · теория 20 мин · практика 25 мин

Мы уже пользовались обобщениями, не называя их так: `Option<T>`, `Result<T, E>`, `Vec<T>`. Угловые скобки означают «этот тип работает с любым содержимым». Теперь научимся писать такие типы сами — и увидим, что обобщения в Rust не стоят ничего во время выполнения.

## Проблема, которую они решают

Допустим, нужна функция поиска максимума в срезе чисел. Потом такая же для строк. Потом для ваших структур. Тело у всех одинаковое, отличается только тип — классическое дублирование.

Обобщённый параметр объявляется в угловых скобках после имени функции:

```rust
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest {
            largest = item;
        }
    }
    largest
}
```

`T` — имя типа-параметра (по традиции одна заглавная буква). Читается: «функция работает с некоторым типом `T`, принимает срез таких значений и возвращает ссылку на одно из них».

Правда, компилироваться это не будет:

```
error[E0369]: binary operation `>` cannot be applied to type `&T`
 --> g1.rs:4:17
  |
4 |         if item > largest { largest = item; }
  |            ---- ^ ------- &T
  |
help: consider restricting type parameter `T` with trait `PartialOrd`
  |
1 | fn largest<T: std::cmp::PartialOrd>(list: &[T]) -> &T {
  |             ++++++++++++++++++++++
```

## Ограничения типов

Ошибка вскрывает главное свойство обобщений в Rust. `T` — это «любой тип», а любой тип не обязан поддерживать сравнение: как сравнить два `HashMap`? Компилятор отказывается писать `>` для чего попало.

Решение он подсказывает сам: **ограничение** (trait bound) — требование, чтобы тип умел что-то конкретное.

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
```

Теперь функция принимает не «любой тип», а «любой тип, поддерживающий сравнение». Проверка происходит **в месте вызова**: подставите неподходящий тип — ошибка укажет на вызов, а не на внутренности функции.

```rust
println!("{}", largest(&[1, 5, 3]));                        // 5
println!("{}", largest(&["груша", "яблоко", "банан"]));     // яблоко
```

В этом принципиальное отличие от шаблонов C++, где ошибка вылезает где-то в глубине раскрытого шаблона и занимает экран. В Rust контракт объявлен в сигнатуре.

Что такое трейт, разберём в следующей статье. Пока достаточно понимать: `PartialOrd` — это «умеет сравниваться», и таких требований можно указать несколько через `+`.

## Обобщённые структуры

Тот же синтаксис:

```rust
#[derive(Debug)]
struct Pair<T> {
    first: T,
    second: T,
}
```

Оба поля здесь **одного** типа: `Pair<i32>` или `Pair<String>`, но не смешанный. Если нужны разные — объявляют два параметра:

```rust
struct Point<T, U> {
    x: T,
    y: U,
}

let mixed = Point { x: 5, y: 4.2 };     // Point<i32, f64>
```

Не плодите параметры без нужды: три-четыре буквы в объявлении — сигнал, что тип пора разбить на несколько.

## Обобщённые реализации

В блоке `impl` параметр тоже объявляют — сразу после ключевого слова:

```rust
impl<T> Pair<T> {
    fn new(first: T, second: T) -> Self {
        Self { first, second }
    }
}
```

`impl<T>` читается как «для любого `T`». Метод `new` доступен всем парам.

А теперь интересное: можно написать блок `impl` **только для тех типов, что удовлетворяют условию**:

```rust
impl<T: PartialOrd + std::fmt::Display> Pair<T> {
    fn larger(&self) -> &T {
        if self.first > self.second { &self.first } else { &self.second }
    }
}
```

Метод `larger` появится у `Pair<i32>`, но не у пары из типов, которые нельзя сравнить. Один тип — разный набор методов в зависимости от содержимого. Приём называется условной реализацией и активно используется в стандартной библиотеке.

## Сколько это стоит

Обычный вопрос: не замедляют ли обобщения программу? В Rust — нет, и это гарантия языка.

При компиляции происходит **мономорфизация**: компилятор находит все использованные варианты и генерирует для каждого отдельный конкретный код. Из `largest<T>`, вызванного с `i32` и с `&str`, получатся две обычные функции — как если бы вы написали их руками.

Отсюда правило: **обобщения бесплатны во время выполнения**. Платите вы временем компиляции и размером бинарника.

Это частный случай принципа, который в Rust называют абстракциями с нулевой стоимостью: высокоуровневая запись не должна проигрывать написанному вручную низкоуровневому коду.

## Что запомнить

- Обобщения избавляют от дублирования кода, отличающегося только типом.
- Параметр объявляется в угловых скобках: `fn f<T>(...)`, `struct S<T>`, `impl<T> S<T>`.
- «Любой тип» почти ничего не умеет — нужны ограничения: `T: PartialOrd`, несколько через `+`.
- Ограничения проверяются в месте вызова, поэтому ошибки понятные и короткие.
- Несколько параметров (`<T, U>`) допустимы, но их обилие — признак перегруженного типа.
- Блок `impl` с ограничением добавляет методы только подходящим типам.
- Мономорфизация делает обобщения бесплатными в рантайме за счёт времени компиляции.

## Практика

**1. Обобщённая функция.** Напишите `first_and_last<T>(list: &[T]) -> (&T, &T)`, возвращающую первый и последний элементы. Вызовите для чисел и для строк. Готово, когда одна функция обслуживает оба вызова.

**2. Ловим отсутствие ограничения.** Напишите функцию, которая складывает два обобщённых значения, и разберите ошибку. Затем добавьте нужное ограничение (подсказка: сложение описывает трейт `std::ops::Add`). Готово, когда функция работает для `i32` и `f64`.

**3. Обобщённая структура.** Опишите `Stack<T>` с методами `push`, `pop` (возвращает `Option<T>`) и `len`. Проверьте на числах и строках. Готово, когда стек работает с обоими типами без дублирования кода.

**4. Условная реализация.** Добавьте `Stack<T>` метод `max`, доступный **только** когда `T` сравним. Проверьте, что он есть у `Stack<i32>`. Затем создайте стек из типа без сравнения и убедитесь, что метода нет. Готово, когда компилятор подтвердил разницу.

**5. Два параметра.** Опишите структуру `Cache<K, V>` с двумя обобщёнными параметрами поверх `HashMap` и методами вставки и чтения. Готово, когда компилируется `Cache<String, u32>` и `Cache<u8, String>`.
