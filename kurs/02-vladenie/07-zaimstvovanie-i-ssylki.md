# 7. Заимствование, ссылки и borrow checker

> ⏱ **~60 минут** · теория 25 мин · практика 35 мин

В прошлой статье мы выяснили: передача значения в функцию забирает владение, и переменная становится непригодной. Возвращать значение обратно каждый раз — мучение. Настоящее решение — **заимствование**: дать функции временный доступ, не отдавая права собственности. Это вторая половина системы владения и главный источник споров с компилятором на первых порах.

## Ссылки

Ссылка создаётся амперсандом и означает «посмотреть, не забирая»:

```rust
fn length(s: &String) -> usize {
    s.len()
}

fn main() {
    let s = String::from("привет");
    let len = length(&s);
    println!("{s} имеет длину {len}");
}
```

Строка осталась во владении `main`. Функция получила `&String` — указатель на данные, которыми не владеет. Когда `length` завершилась, освобождать ей было нечего.

Такой доступ и называется **заимствованием** (borrowing): взяли на время и обязаны вернуть.

По умолчанию ссылка, как и переменная, неизменяема:

```rust
// ❌ не компилируется
fn add_mark(s: &String) {
    s.push_str("!");
}
```

Чтобы менять данные через ссылку, нужны две вещи: изменяемая переменная и изменяемая ссылка.

```rust
fn add_mark(s: &mut String) {
    s.push_str("!");
}

fn main() {
    let mut s = String::from("привет");
    add_mark(&mut s);
    println!("{s}");     // привет!
}
```

Заметьте, `&mut` пишется в трёх местах: в типе параметра, при вызове и `mut` при объявлении переменной. Если забыть последнее, компилятор объяснит:

```
error[E0596]: cannot borrow `s` as mutable, as it is not declared as mutable
help: consider changing this to be mutable
  |
2 |     let mut s = String::from("привет");
  |         +++
```

## Правило заимствования

Здесь начинается самое важное. В любой момент времени для одного значения может существовать **либо**:

- сколько угодно неизменяемых ссылок,
- **либо** ровно одна изменяемая.

Одновременно — нельзя. Проверим:

```rust
// ❌ не компилируется
let mut s = String::from("привет");
let r1 = &mut s;
let r2 = &mut s;
println!("{r1} {r2}");
```

```
error[E0499]: cannot borrow `s` as mutable more than once at a time
 --> b2.rs:4:14
  |
3 |     let r1 = &mut s;
  |              ------ first mutable borrow occurs here
4 |     let r2 = &mut s;
  |              ^^^^^^ second mutable borrow occurs here
```

Смешивать тоже нельзя:

```rust
// ❌ не компилируется
let r1 = &s;
let r2 = &mut s;
println!("{r1} {r2}");
```

```
error[E0502]: cannot borrow `s` as mutable because it is also borrowed as immutable
```

Зачем такая строгость? Правило устраняет **гонку данных** — ситуацию, когда одна часть кода читает данные, пока другая их меняет. В многопоточных программах это источник плавающих багов, которые невозможно воспроизвести. Rust делает их невозможными на этапе компиляции.

Но и в однопоточном коде правило спасает. Представьте: вы перебираете список и внутри цикла удаляете из него элементы. Данные из-под вас «уезжают», и в C++ это обернулось бы обращением к освобождённой памяти. Здесь — ошибка компиляции.

## Область действия заимствования

Правило звучит жёстко, но на практике мешает редко, потому что **заимствование действует не до конца блока, а до последнего использования ссылки**:

```rust
let mut s = String::from("привет");

let r1 = &s;
println!("{r1}");        // здесь r1 использован в последний раз

let r2 = &mut s;         // и заимствование уже закончилось
r2.push_str("!");
println!("{r2}");
```

```
привет
привет!
```

Обе ссылки существуют в одном блоке, но их «времена жизни» не пересекаются, поэтому конфликта нет. Эта оптимизация компилятора называется нелексическими временами жизни (NLL), и благодаря ей код обычно пишется естественно.

Практический вывод: если borrow checker ругается, часто достаточно **сузить область использования ссылки** — переставить строки или вынести кусок в отдельный блок.

## Висячие ссылки

В языках с ручным управлением памятью есть классическая ошибка: вернуть указатель на данные, которые уже освобождены. Попробуем:

```rust
// ❌ не компилируется
fn dangle() -> &String {
    let s = String::from("привет");
    &s
}
```

```
error[E0106]: missing lifetime specifier
 --> b5.rs:1:16
  |
1 | fn dangle() -> &String {
  |                ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value,
    but there is no value for it to be borrowed from
help: instead, you are more likely to want to return an owned value
```

Разберём, что произошло. Строка создана внутри `dangle` — значит, при выходе из функции она освобождается. Ссылка на неё указывала бы в никуда. Компилятор это увидел и остановил сборку.

Решение — вернуть само значение, отдав владение:

```rust
fn no_dangle() -> String {
    String::from("привет")
}
```

Упоминание «lifetime» в ошибке — привет из статьи 18. Пока достаточно знать: **компилятор следит, чтобы ссылка не пережила данные, на которые указывает**.

## Как спорить с borrow checker

Первые недели он будет отклонять код, который кажется правильным. Порядок действий:

1. **Прочитать ошибку целиком.** Коды `E0499`, `E0502`, `E0596` — три самых частых, и каждая помечает стрелками, где взяли заимствование и где оно ещё живо.
2. **Спросить себя: кто должен владеть данными?** Часто конфликт означает, что структура данных выбрана неудачно, а не что компилятор придирается.
3. **Попробовать сузить область ссылки** — перенести использование ближе к месту создания.
4. **Клонировать — в последнюю очередь.** `.clone()` затыкает ошибку, но прячет вопрос о владении, а не отвечает на него.

## Что запомнить

- `&value` — заимствование: доступ без передачи владения. `&mut value` — заимствование с правом изменять.
- Для изменяемой ссылки сама переменная тоже должна быть объявлена с `mut`.
- Главное правило: либо много неизменяемых ссылок, либо одна изменяемая. Не одновременно.
- Правило существует, чтобы исключить гонки данных и изменение данных во время их чтения.
- Заимствование живёт до последнего использования ссылки, а не до конца блока (NLL).
- Ссылка не может пережить данные: висячие ссылки ловятся при компиляции.
- Если borrow checker спорит — сначала пересмотрите владение, и только потом клонируйте.

## Практика

**1. Заимствование вместо владения.** Перепишите функцию `consume(s: String)` из прошлой статьи так, чтобы она принимала ссылку. Вызовите её трижды подряд с одной переменной. Готово, когда программа работает без `clone()`.

**2. Изменение через ссылку.** Напишите функцию `shout(s: &mut String)`, которая переводит строку в верхний регистр и добавляет `!!!` (подсказка: `to_uppercase` возвращает новую строку — подумайте, как присвоить её по ссылке через `*`). Готово, когда после вызова исходная переменная изменилась.

**3. Коллекция ошибок borrow checker.** Воспроизведите три ошибки: `E0596` (изменяемая ссылка на неизменяемую переменную), `E0499` (две изменяемые ссылки), `E0502` (смешали изменяемую с неизменяемой). Готово, когда есть таблица «код ошибки → что нарушено → как починить».

**4. Сужаем заимствование.** Возьмите код с ошибкой `E0502` и почините его **без** `clone()` — только переставляя строки. Готово, когда программа компилируется и обе ссылки по-прежнему в одном блоке.

**5. Висячая ссылка.** Напишите функцию, возвращающую ссылку на локальную строку, и разберите ошибку. Затем почините двумя способами: возвратом владения и передачей ссылки на данные снаружи через параметр. Готово, когда оба варианта собираются.
