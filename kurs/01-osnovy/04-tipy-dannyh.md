# 4. Типы данных: числа, `bool`, `char`, кортежи и массивы

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Rust — статически типизированный язык: тип каждого значения известен на этапе компиляции. При этом писать типы вручную приходится редко — компилятор выводит их сам. Разберём базовые типы, из которых складывается всё остальное, и заодно увидим, почему Rust отказывается складывать целое число с дробным.

## Аннотации типов

Обычно тип не пишут — компилятор выводит его из значения:

```rust
let x = 5;        // i32
let y = 2.5;      // f64
```

Но иногда вывести тип невозможно, и тогда компилятор потребует аннотацию явно:

```rust
let x: i32 = 5;
let y: f64 = 2.5;
```

Такое случается, например, при разборе строки в число: из текста `"42"` можно получить и `i32`, и `u8`, и `f64` — компилятор не угадывает, а спрашивает.

## Целые числа

Тип целого числа задаётся двумя параметрами: знаковость и разрядность.

- **8 бит** — `i8` со знаком (диапазон −128 … 127) и `u8` без знака.
- **16 бит** — `i16` (−32 768 … 32 767) и `u16`.
- **32 бита** — `i32` (примерно ±2,1 млрд) и `u32`.
- **64 бита** — `i64` (примерно ±9,2 · 10¹⁸) и `u64`.
- **128 бит** — `i128` и `u128`, диапазон огромный.
- **Размер платформы** — `isize` и `usize`, зависит от системы.

**Умолчание — `i32`.** Если тип не указан и вывести неоткуда, будет он: разумный компромисс по скорости и диапазону.

`usize` — отдельная история. Это тип, которым индексируют коллекции: его разрядность равна разрядности указателя (на современных машинах 64 бита). Именно `usize` возвращает метод `.len()`.

Для читаемости в числах можно ставить подчёркивания: `1_000_000`.

## Переполнение

Что будет, если положить в `u8` (максимум 255) значение 256?

```rust
fn main() {
    let mut x: u8 = 255;
    x += 1;
}
```

```
thread 'main' panicked at o1.rs:3:5:
attempt to add with overflow
```

Программа аварийно завершилась — это **паника** (panic). Так ведёт себя отладочная сборка.

В релизной сборке проверки переполнения отключены ради скорости, и число «оборачивается»: 255 + 1 даст 0. Это не считается ошибкой памяти и не нарушает безопасность, но результат почти наверняка не тот, что вы хотели.

Отсюда практический вывод: **тестируйте в debug-сборке**. Она поймает переполнение там, где release молча посчитает ерунду. А если оборачивание нужно осознанно, есть явные методы — `wrapping_add`, `checked_add`, `saturating_add`.

## Числа с плавающей точкой и отсутствие неявных приведений

Типов два: `f32` и `f64`. Умолчание — `f64`.

Главная особенность, которая удивляет новичков: Rust **не приводит числовые типы автоматически**.

```rust
// ❌ не компилируется
fn main() {
    let x: i32 = 5;
    let y: f64 = 2.0;
    let z = x + y;
}
```

```
error[E0277]: cannot add `f64` to `i32`
 --> o5.rs:4:15
  |
4 |     let z = x + y;
  |               ^ no implementation for `i32 + f64`
```

Никакого молчаливого расширения типа, как в C или Java. Преобразование пишется явно через `as`:

```rust
let z = x as f64 + y;
```

Многословно, зато вы всегда видите место, где число меняет представление и где может потеряться точность.

## Логический тип и символы

`bool` принимает `true` или `false` и занимает один байт.

`char` — не байт, а **скалярное значение Unicode** размером 4 байта. Поэтому в него помещается не только латиница:

```rust
let heart = '♥';
let letter = 'ы';
```

Символы пишут в одинарных кавычках, строки — в двойных. Это разные типы, и путать их нельзя.

Важная тонкость: `'ы'` — один `char`, но в UTF-8 он занимает 2 байта. Отсюда растёт вся будущая сложность работы со строками, к которой вернёмся в статье 8.

## Кортежи

Кортеж (tuple) объединяет значения **разных** типов в одну сущность фиксированной длины:

```rust
fn main() {
    let point: (i32, f64, char) = (500, 6.4, 'A');

    let (a, b, c) = point;        // деструктуризация
    println!("{a} {b} {c}");

    println!("{}", point.0);      // доступ по индексу
}
```

```
500 6.4 A
500
```

Два способа добраться до содержимого: **деструктуризация** (разложить на переменные) и **индекс через точку**, начиная с нуля.

Кортеж без элементов — `()` — называется *unit*. Это тип-пустышка: его возвращают функции, которые ничего не возвращают. Дальше он будет встречаться постоянно.

## Массивы

Массив хранит значения **одного** типа, и его длина фиксируется на этапе компиляции:

```rust
let numbers: [i32; 5] = [1, 2, 3, 4, 5];
let zeros = [0; 5];              // пять нулей
println!("{}", numbers[0]);
```

Запись `[i32; 5]` читается как «пять значений типа `i32`». Длину изменить нельзя — для растущих списков есть `Vec`, о нём в статье 12.

Что будет при выходе за границу? Если индекс известен при компиляции, программа просто не соберётся:

```
error: this operation will panic at runtime
 --> o2.rs:4:20
  |
4 |     println!("{}", numbers[index]);
  |                    ^^^^^^^^^^^^^^ index out of bounds: the length is 3 but the index is 5
```

Если индекс вычисляется во время работы, проверка происходит в момент обращения:

```
thread 'main' panicked at o4.rs:4:20:
index out of bounds: the len is 3 but the index is 5
```

Сравните с C, где такое обращение молча прочитает чужую память. Rust предпочитает честно упасть — эта проверка и есть та самая «безопасность», ради которой платят производительностью в доли процента.

## Что запомнить

- Типы известны при компиляции, но пишутся руками редко — работает вывод типов.
- Умолчания: `i32` для целых, `f64` для дробных. Индексы и длины — `usize`.
- Переполнение в debug-сборке вызывает панику, в release — тихо оборачивается. Тестируйте в debug.
- Неявных числовых приведений нет: `i32 + f64` не скомпилируется, нужно явное `as`.
- `char` — 4 байта и любой символ Unicode, в одинарных кавычках.
- Кортеж — разные типы, фиксированная длина; доступ через деструктуризацию или `.0`.
- Массив — один тип, фиксированная длина `[T; N]`; выход за границу ловится компилятором или паникой.

## Практика

**1. Границы типов.** Выведите максимальные значения `u8`, `i32` и `u64` (подсказка: `u8::MAX`). Проверьте по таблице из статьи. Готово, когда числа совпали с ожидаемыми.

**2. Переполнение своими руками.** Заведите `u8` со значением 250 и прибавьте 10 в цикле из... впрочем, циклы будут в следующей статье — просто прибавьте 10 одной операцией. Посмотрите на панику. Затем соберите ту же программу с `--release` и сравните результат. Готово, когда вы видели оба поведения и можете объяснить разницу.

**3. Явные приведения.** Напишите программу, которая делит `7` на `2` как целые числа, а затем как дробные, и печатает оба результата. Готово, когда программа печатает 3 и 3.5.

**4. Кортеж как запись.** Опишите кортежем данные студента: имя (`&str`), возраст (`u8`), средний балл (`f64`). Выведите данные двумя способами — через деструктуризацию и через индексы. Готово, когда оба способа дают одинаковый вывод.

**5. Массив и границы.** Создайте массив из семи названий дней недели. Выведите первый и последний элементы, не подставляя число 6 руками (подсказка: `.len()`). Затем намеренно обратитесь к восьмому элементу и запишите, что скажет компилятор. Готово, когда у вас есть рабочая программа и текст ошибки.

3. Как ведёт себя переполнение целого числа в debug- и в release-сборке? Какой практический вывод из этого следует?
4. Почему `x + y` не компилируется, если `x: i32`, а `y: f64`? Чем это лучше молчаливого приведения?
5. Сколько байт занимает `char` и почему не один?
6. В чём разница между кортежем и массивом? Когда что выбирать?
7. Программа обращается к элементу массива за его границей. Когда эту ошибку поймает компилятор, а когда — только запуск?
