# 3. Переменные, константы, изменяемость и затенение

> ⏱ **~45 минут** · теория 15 мин · практика 30 мин

Первая по-настоящему «растовская» тема. В большинстве языков переменная по умолчанию изменяема, и это кажется естественным. Rust переворачивает умолчание: переменная неизменяема, пока вы явно не попросите обратного. Разберёмся, почему так сделано и какие инструменты есть взамен привычного «просто присвою новое значение».

## Переменная неизменяема по умолчанию

Объявление переменной — ключевое слово `let`:

```rust
fn main() {
    let x = 5;
    println!("Значение x: {x}");
}
```

Запись `{x}` внутри `println!` подставляет значение переменной по имени — так короче, чем `{}` с отдельным аргументом.

А теперь попробуем изменить `x`:

```rust
// ❌ не компилируется
fn main() {
    let x = 5;
    x = 6;
}
```

```
error[E0384]: cannot assign twice to immutable variable `x`
 --> e1.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++
```

Зачем такое ограничение? Причины ровно две, и обе практические.

**Читаемость.** Увидев `let x = 5`, вы знаете: ниже по коду `x` останется пятёркой. Не нужно проглядывать сотню строк в поисках того места, где значение подменили.

**Безопасность многопоточности.** Данные, которые никто не меняет, можно безопасно читать из нескольких потоков одновременно. Неизменяемость по умолчанию — фундамент, на котором позже вырастут гарантии Rust про отсутствие гонок данных.

## Изменяемость по требованию

Когда значение действительно должно меняться, добавляется `mut` (от *mutable*):

```rust
fn main() {
    let mut counter = 0;
    counter = counter + 1;
    counter = counter + 1;
    println!("Счётчик: {counter}");
}
```

```
Счётчик: 2
```

`mut` — это не только разрешение компилятору. Это сообщение читателю: «за этой переменной следи, она меняется». Поэтому не стоит ставить `mut` профилактически, «на всякий случай»: компилятор всё равно предупредит, если изменяемость не понадобилась.

## Константы

Константа объявляется через `const` и отличается от неизменяемой переменной тремя вещами:

```rust
const SECONDS_IN_DAY: u32 = 60 * 60 * 24;

fn main() {
    println!("Секунд в сутках: {SECONDS_IN_DAY}");
}
```

**Тип указывать обязательно.** Здесь это `u32` — целое число без знака (про типы подробно в следующей статье). Для `let` компилятор чаще всего выводит тип сам, для `const` — никогда:

```rust
// ❌ не компилируется
const MAX_USERS = 100;
```

```
error: missing type for `const` item
 --> e2.rs:2:20
  |
2 |     const MAX_USERS = 100;
  |                    ^ help: provide a type for the constant: `: i32`
```

**Значение вычисляется на этапе компиляции.** Поэтому в константу нельзя положить результат работы программы — например, введённое пользователем число. Зато выражение вроде `60 * 60 * 24` посчитается при сборке, и в готовом бинарнике окажется просто `86400`.

**Константу нельзя объявить с `mut`.** Неизменяемость здесь абсолютная, а не «по умолчанию».

Имена констант пишут заглавными буквами через подчёркивание — `SECONDS_IN_DAY`. Объявлять их можно где угодно, в том числе вне функций, что удобно для значений, нужных всей программе.

## Затенение

Иногда нужно взять значение, преобразовать и работать дальше уже с результатом. В Rust для этого не нужна изменяемость — достаточно объявить переменную с тем же именем ещё раз. Это называется **затенением** (shadowing):

```rust
fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
    println!("Количество пробелов: {spaces}");
}
```

```
Количество пробелов: 3
```

Здесь `spaces` сначала строка, потом число — её длина (`.len()` — метод, возвращающий длину; методы разберём позже). Второй `let` не изменил переменную, а **создал новую**, закрыв собой первую.

Именно поэтому смена типа сработала. С `mut` такой фокус не пройдёт:

```rust
// ❌ не компилируется
fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
}
```

```
error[E0308]: mismatched types
 --> s2.rs:3:14
  |
2 |     let mut spaces = "   ";
  |                      ----- expected due to this value
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`
```

Разница принципиальная: `mut` меняет значение внутри переменной, тип при этом остаётся навсегда. Затенение создаёт новую переменную, поэтому тип может быть любым.

Затенение действует в пределах области видимости. Внутри блока `{ }` можно затенить переменную, и наружу это не просочится:

```rust
fn main() {
    let x = 5;
    {
        let x = x * 2;
        println!("Внутри блока: {x}");
    }
    println!("Снаружи: {x}");
}
```

```
Внутри блока: 10
Снаружи: 5
```

Типичное применение затенения — обработка ввода: получили строку, превратили в число, дальше работаете с числом, не выдумывая имена `input_str`, `input_num`, `input_parsed`.

## Неиспользуемые переменные

Если переменная объявлена, но не используется, компилятор предупредит:

```
warning: unused variable: `user_name`
 --> u1.rs:2:9
  |
2 |     let user_name = "Алия";
  |         ^^^^^^^^^ help: if this is intentional, prefix it with an underscore: `_user_name`
```

Это предупреждение, а не ошибка — программа соберётся. Но чаще всего оно означает опечатку или забытый код. Если переменная нужна намеренно (так бывает), имя начинают с подчёркивания: `_user_name`.

## Что запомнить

- `let` создаёт **неизменяемую** переменную — это умолчание Rust, а не исключение.
- `mut` добавляет изменяемость и одновременно предупреждает читателя: «эта переменная меняется».
- `const` требует явного типа, вычисляется на этапе компиляции, пишется `SCREAMING_CASE` и не бывает изменяемой.
- Затенение — повторный `let` с тем же именем. Создаёт **новую** переменную, поэтому позволяет сменить тип.
- `mut` менять тип не позволяет: тип переменной фиксируется при объявлении.
- Затенение ограничено областью видимости: затенили внутри блока — снаружи всё по-старому.
- Неиспользуемая переменная даёт предупреждение; осознанно неиспользуемую называют с `_` в начале.

## Практика

**1. Счётчик.** Напишите программу с переменной `attempts`, которая начинается с нуля и трижды увеличивается на единицу с выводом значения после каждого шага. Готово, когда программа печатает 1, 2, 3 и собирается без предупреждений.

**2. Константа.** Объявите вне функции константу с количеством минут в неделе, посчитанную выражением (не готовым числом). Выведите её. Готово, когда программа печатает 10080, а в коде видно, из чего это число получилось.

**3. Ловим компилятор.** Воспроизведите три ошибки и запишите их коды: присваивание неизменяемой переменной, константа без типа, попытка сменить тип у `mut`-переменной. Готово, когда у вас есть табличка «что сломал → код ошибки → что предложил компилятор».

**4. Затенение вместо новых имён.** Заведите переменную `temperature` со строкой `"25"`. Затените её числом (подсказка: `"25".len()` вам не подойдёт — нужен разбор строки в число, поищите в документации метод `parse`). Затем затените ещё раз, прибавив 10. Готово, когда программа печатает 35, а имя переменной всё это время одно.

**5. Область видимости.** Напишите программу, где переменная `score` равна 100, внутри вложенного блока затеняется значением 200, а после блока снова печатается. Предскажите вывод **до** запуска, потом проверьте. Готово, когда предсказание совпало с результатом.

## Вопросы для самопроверки

1. Почему в Rust переменные неизменяемы по умолчанию? Назовите две причины.
2. Чем `const` отличается от `let` без `mut`? Назовите три отличия.
3. Почему в константу нельзя положить значение, введённое пользователем?
4. В чём разница между затенением и `mut`? Почему затенение позволяет сменить тип, а `mut` — нет?
5. Что выведет программа, если внутри блока `{ }` затенить переменную, а печатать её после блока?
6. Вы поставили `mut`, но переменная нигде не меняется. Что скажет компилятор и почему это полезно?
7. Когда имеет смысл назвать переменную с подчёркивания в начале — `_result`?
