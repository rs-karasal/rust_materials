# 12. Коллекции: `Vec`, `HashMap`, `HashSet`

> ⏱ **~55 минут** · теория 20 мин · практика 35 мин

Массив из статьи 4 хорош, пока длина известна заранее. Реальные данные так себя не ведут. Коллекции стандартной библиотеки хранят данные в куче и умеют расти — а значит, к ним в полной мере применимы правила владения. Разберём три самых нужных.

## `Vec<T>` — растущий список

Создание и добавление:

```rust
let mut v: Vec<i32> = Vec::new();
v.push(1);

let mut v = vec![1, 2, 3];      // макрос-сокращение
v.push(4);
```

Все элементы одного типа — как в массиве. Разница в том, что длина меняется во время работы программы.

Доступ к элементу возможен двумя способами, и выбор между ними важен:

```rust
let third = &v[2];          // паникует, если индекса нет
let third = v.get(2);       // возвращает Option<&i32>
```

```rust
println!("{:?} {:?}", v.get(0), v.get(10));
// Some(1) None
```

Квадратные скобки уместны, когда выход за границу означает ошибку в программе. `get` — когда индекс приходит извне и «нет такого элемента» это нормальная ситуация, которую надо обработать через `Option`.

Перебор — циклом `for` по ссылке:

```rust
let mut total = 0;
for value in &v {
    total += value;
}

for value in &mut v {
    *value *= 10;
}
```

Заимствуем `&v` для чтения и `&mut v` для изменения. Звёздочка в `*value *= 10` — **разыменование**: `value` здесь ссылка, и звёздочка говорит «работай со значением по ссылке, а не с самой ссылкой».

Если написать `for value in v` без амперсанда, цикл **заберёт владение** вектором, и после него `v` использовать нельзя. Иногда именно это и нужно, но чаще это случайность.

## Коллекции и borrow checker

Вот ошибка, на которой спотыкаются все:

```rust
// ❌ не компилируется
let mut v = vec![1, 2, 3];
let first = &v[0];
v.push(4);
println!("{first}");
```

```
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable
 --> p.rs:4:5
  |
3 |     let first = &v[0];
  |                  - immutable borrow occurs here
4 |     v.push(4);
  |     ^^^^^^^^^ mutable borrow occurs here
```

Почему нельзя? Кажется, что добавление в конец не трогает первый элемент. Но `Vec` хранит данные единым куском памяти, и когда место кончается, он **выделяет новый кусок побольше и переносит туда всё содержимое**. Старый адрес становится недействительным — и `first` указывал бы в никуда.

В C++ это классический баг с невалидным итератором, который проявляется случайно и только на некоторых размерах данных. Здесь — ошибка компиляции. Правило заимствования из статьи 7 оказалось не бюрократией, а защитой от вполне конкретной беды.

## `HashMap<K, V>` — словарь

Хранит пары «ключ — значение», порядок не гарантируется:

```rust
use std::collections::HashMap;

let mut scores: HashMap<String, u32> = HashMap::new();
scores.insert(String::from("Алия"), 10);
scores.insert(String::from("Данияр"), 20);

println!("{:?}", scores.get("Алия"));    // Some(10)
```

В отличие от `Vec` и `String`, `HashMap` не входит в автоматически подключаемый набор — его нужно импортировать.

`get` возвращает `Option<&V>`, потому что ключа может не быть. Обратите внимание: ищем по `"Алия"` — литералу `&str`, хотя ключи `String`. Это работает благодаря тому же преобразованию, что и в статье 8.

**Владение**: типы вроде `String` при вставке **перемещаются** в словарь. Логично — теперь ими владеет он.

Ключевой метод, который стоит выучить, — `entry`:

```rust
*scores.entry(String::from("Алия")).or_insert(0) += 5;   // было 10, стало 15
scores.entry(String::from("Ерлан")).or_insert(7);        // не было — вставили 7
```

`entry` возвращает «место» под ключом, а `or_insert` кладёт туда значение по умолчанию, если пусто, и в любом случае отдаёт изменяемую ссылку. Без него пришлось бы каждый раз писать проверку «есть ли ключ».

Классическое применение — подсчёт:

```rust
let text = "мама мыла раму мама";
let mut freq = HashMap::new();

for word in text.split_whitespace() {
    *freq.entry(word).or_insert(0) += 1;
}
// [("мама", 2), ("мыла", 1), ("раму", 1)]
```

Три строки на частотный словарь — идиома, которую вы будете использовать постоянно.

## `HashSet<T>` — множество

Хранит уникальные значения и быстро отвечает на вопрос «есть ли такой элемент»:

```rust
use std::collections::HashSet;

let mut set = HashSet::new();
set.insert("a");
println!("{}", set.insert("a"));    // false — уже было
```

`insert` возвращает `bool`: `true`, если значение новое. Удобно для отсеивания дубликатов за один проход. Есть и операции над множествами: `union`, `intersection`, `difference`.

## Что выбрать

- **Список по порядку, добавление в конец** — `Vec<T>`.
- **Поиск значения по ключу** — `HashMap<K, V>`.
- **Проверка «видели ли мы это»** — `HashSet<T>`.
- **То же, но с отсортированным обходом** — `BTreeMap` или `BTreeSet`.
- **Очередь с добавлением и изъятием с обоих концов** — `VecDeque<T>`.

Правило по умолчанию: **берите `Vec`**. Он покрывает большинство задач и быстрее словаря на малых объёмах — перебрать десяток элементов дешевле, чем считать хеш.

`BTreeMap` отличается от `HashMap` тем, что хранит ключи отсортированными: обход даёт предсказуемый порядок, но операции чуть медленнее.

## Что запомнить

- `Vec<T>` — растущий список однотипных значений в куче; создаётся через `Vec::new()` или `vec![]`.
- `v[i]` паникует при выходе за границу, `v.get(i)` возвращает `Option` — выбирайте осознанно.
- Перебор `&v` заимствует, `&mut v` позволяет менять (со звёздочкой-разыменованием), `v` без амперсанда забирает владение.
- Нельзя держать ссылку на элемент и одновременно менять коллекцию: при росте `Vec` данные переезжают в памяти.
- `HashMap` требует импорта, возвращает `Option` при поиске и забирает владение вставленными значениями.
- `entry(...).or_insert(...)` — основной способ обновить значение или задать умолчание.
- `HashSet` хранит уникальные значения; `insert` возвращает `false` для дубликата.

## Практика

**1. Статистика по вектору.** Дан вектор чисел. Найдите сумму, среднее, минимум и максимум. Готово, когда программа считает всё за один проход по ссылке, не забирая владение.

**2. Два вида доступа.** Обратитесь к несуществующему элементу вектора двумя способами — через `[]` и через `get`. Готово, когда первый вариант паникует, а второй печатает `None`.

**3. Ловим переезд данных.** Воспроизведите ошибку `E0502` со ссылкой на элемент и `push`. Затем почините код, не убирая ни одну из операций. Готово, когда программа работает и вы можете объяснить, почему изначально это было опасно.

**4. Частотный словарь.** Посчитайте, сколько раз каждое слово встречается в предложении. Выведите результат отсортированным по слову. Готово, когда в коде использован `entry`, а не проверка на наличие ключа.

**5. Дубликаты.** Дан вектор чисел с повторами. Одним проходом получите: вектор уникальных значений в исходном порядке и множество тех, что встретились более одного раза. Готово, когда обе структуры заполняются в одном цикле.
