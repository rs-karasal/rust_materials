# 28. `serde`, JSON и работа с файлами

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Почти любая реальная программа читает конфигурацию, разбирает ответ API или сохраняет состояние на диск. В Rust за превращение данных в структуры и обратно отвечает `serde` — крейт настолько устоявшийся, что его считают почти частью языка. Разберём его вместе с базовой работой с файлами.

## Файлы: простой путь

Для небольших файлов есть две функции, покрывающие большинство задач:

```rust
use std::fs;

fs::write("config.json", &content)?;
let text = fs::read_to_string("config.json")?;
```

Обе возвращают `Result` — файл может не существовать, прав может не хватить. Оператор `?` из статьи 13 здесь работает как обычно.

Когда файл большой, читать его целиком в память нельзя. Тогда — построчно, через буферизованный читатель:

```rust
use std::io::{BufRead, BufReader};

let reader = BufReader::new(fs::File::open("lines.txt")?);
for (i, line) in reader.lines().enumerate() {
    println!("{i}: {}", line?);
}
```

`BufReader` накапливает данные блоками вместо обращения к диску на каждый байт — без него построчное чтение работает в разы медленнее. Метод `lines()` даёт итератор, поэтому применимо всё из статьи 20: `filter`, `map`, `take`.

Запись устроена симметрично:

```rust
use std::io::Write;

let mut f = fs::File::create("lines.txt")?;
writeln!(f, "первая")?;
```

`write!` и `writeln!` работают как `println!`, но пишут в файл. Для интенсивной записи их оборачивают в `BufWriter`.

Полезные функции: `fs::remove_file`, `fs::create_dir_all`, `fs::copy`, `Path::exists`.

## `serde`: два трейта

Крейт строится на паре трейтов: `Serialize` (структура → формат) и `Deserialize` (формат → структура). Реализуют их через `derive`:

```toml
serde = { version = "1", features = ["derive"] }
serde_json = "1"
```

```rust
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize)]
struct Config {
    name: String,
    port: u16,
    debug: bool,
}
```

Сериализация и разбор — по одной строке:

```rust
let json = serde_json::to_string_pretty(&cfg)?;
let parsed: Config = serde_json::from_str(raw)?;
```

```json
{
  "name": "сервис",
  "port": 8080,
  "debug": true
}
```

Важная деталь архитектуры: `serde` **не привязан к JSON**. Он описывает структуру данных, а формат подключается отдельным крейтом: `serde_json`, `toml`, `serde_yaml`, `bincode`. Одна и та же структура читается из любого — код не меняется.

## Проверка на этапе разбора

Ключевое отличие от динамических языков. В Python или JavaScript разобранный JSON — словарь, и отсутствие поля вы обнаружите позже, при обращении. Здесь несоответствие ловится сразу:

```rust
let bad = r#"{"name":"нет порта"}"#;
serde_json::from_str::<Config>(bad)
```

```
ошибка разбора: missing field `port` at line 1 column 28
```

Ошибка указывает поле, строку и позицию. Если разбор прошёл — структура заполнена целиком, и дальше можно работать без проверок. Валидация формата фактически бесплатна: её описывает объявление структуры.

Кстати, `r#"..."#` — сырой строковый литерал: внутри не нужно экранировать кавычки. Удобно для JSON и регулярных выражений.

## Атрибуты

Реальные данные редко совпадают с идеальной структурой. Настраивается это атрибутами:

```rust
#[derive(Debug, Serialize, Deserialize)]
struct Config {
    name: String,
    port: u16,

    #[serde(default)]
    debug: bool,

    #[serde(rename = "maxUsers")]
    max_users: u32,

    #[serde(skip_serializing_if = "Option::is_none")]
    comment: Option<String>,
}
```

- `default` — если поля нет, взять значение по умолчанию. Именно так делают необязательные настройки.
- `rename` — имя в JSON отличается от имени поля. Для сплошного переименования есть `#[serde(rename_all = "camelCase")]` над всей структурой.
- `skip_serializing_if` — не выводить поле при условии. В примере `comment: None` в JSON не попал.

Ещё пригодятся: `flatten` — «вклеить» вложенную структуру в родительскую, `skip` — игнорировать поле полностью, `with` — свой сериализатор для типа.

`Option<T>` работает естественно: `null` или отсутствие поля превращаются в `None`.

## Конфигурация: типичная связка

Складывая всё вместе, получаем стандартный подход к настройкам приложения:

```rust
fn load_config(path: &str) -> Result<Config, Box<dyn std::error::Error>> {
    let text = fs::read_to_string(path)?;
    let config: Config = serde_json::from_str(&text)?;
    Ok(config)
}
```

Три строки, и на выходе — проверенная структура вместо словаря с сюрпризами. Для TOML (формат `Cargo.toml`) код тот же, меняется только крейт.

## Что запомнить

- `fs::read_to_string` и `fs::write` покрывают работу с небольшими файлами; всё возвращает `Result`.
- Большие файлы читают построчно через `BufReader`, иначе производительность падает в разы.
- `lines()` даёт итератор — применимы `filter`, `map` и остальные адаптеры.
- `serde` описывает структуру данных, формат подключается отдельным крейтом (`serde_json`, `toml`, `bincode`).
- `#[derive(Serialize, Deserialize)]` — всё, что нужно для большинства структур.
- Несоответствие данных ловится в момент разбора, с указанием поля и позиции.
- Атрибуты `default`, `rename`, `rename_all`, `skip_serializing_if` покрывают почти все расхождения между структурой и реальным JSON.
- `r#"..."#` — сырая строка без экранирования.

## Практика

**1. Чтение и запись.** Напишите программу, создающую текстовый файл из пяти строк, читающую его целиком и выводящую количество символов. Готово, когда обе операции обрабатывают ошибки через `?`.

**2. Построчная обработка.** Прочитайте файл через `BufReader` и выведите только строки, содержащие заданное слово, с их номерами. Готово, когда использован итератор `lines()` и хотя бы один адаптер.

**3. Первая сериализация.** Опишите структуру «задача» с полями «название», «выполнена», «приоритет». Сериализуйте вектор задач в JSON-файл, затем прочитайте обратно. Готово, когда данные совпадают до и после.

**4. Неидеальные данные.** Возьмите JSON, где одно поле названо иначе, другое отсутствует, третье равно `null`. Подберите атрибуты, чтобы он разобрался в вашу структуру. Готово, когда разбор проходит без ошибок.

**5. Смена формата.** Переведите программу из задачи 3 с JSON на TOML, подключив крейт `toml`. Готово, когда изменились только строки с вызовом сериализатора, а структура осталась прежней.
