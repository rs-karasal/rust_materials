# 20. Итераторы: `map`, `filter`, `fold` и свой итератор

> ⏱ **~55 минут** · теория 20 мин · практика 35 мин

Итератор — способ пройти по последовательности значений, не заботясь о том, как она устроена внутри. В Rust это не просто удобство: цепочки итераторов заменяют циклы почти везде, читаются лучше и при этом не проигрывают им в скорости. Разберём, как ими пользоваться и как написать свой.

## Трейт `Iterator`

Всё держится на одном трейте с одним обязательным методом:

```rust
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}
```

`type Item` — ассоциированный тип: что именно выдаёт итератор. `next` возвращает следующий элемент или `None`, когда всё кончилось. Всё остальное — десятки готовых методов, построенных поверх `next`.

Именно так работает цикл `for`: он берёт итератор и в цикле дёргает `next`.

У коллекций есть три способа получить итератор, и разница между ними — про владение:

| Метод | Выдаёт | Что с коллекцией |
|---|---|---|
| `.iter()` | `&T` | остаётся доступной |
| `.iter_mut()` | `&mut T` | остаётся, элементы можно менять |
| `.into_iter()` | `T` | поглощается, владение переходит |

## Ленивость

Ключевое свойство: итераторы **ничего не делают, пока их не потребят**.

```rust
let v = vec![1, 2, 3];
v.iter().map(|x| println!("{x}"));
```

```
warning: unused `Map` that must be used
  = note: iterators are lazy and do nothing unless consumed
```

Ни одна строка не напечаталась. `map` только описал будущее преобразование и вернул новый итератор.

Отсюда деление методов на две группы.

**Адаптеры** возвращают новый итератор и ничего не вычисляют: `map`, `filter`, `take`, `skip`, `zip`, `enumerate`, `rev`, `chain`.

**Потребители** запускают работу и выдают результат: `collect`, `sum`, `product`, `count`, `fold`, `find`, `any`, `all`, `for_each`.

Цепочка всегда заканчивается потребителем — иначе не произойдёт ничего.

## Основные адаптеры

```rust
let v = vec![1, 2, 3, 4, 5, 6];

let squares: Vec<i32> = v.iter().map(|x| x * x).collect();
// [1, 4, 9, 16, 25, 36]

let evens: Vec<&i32> = v.iter().filter(|x| *x % 2 == 0).collect();
// [2, 4, 6]
```

`map` преобразует каждый элемент, `filter` оставляет подходящие. Обратите внимание на звёздочки: `filter` передаёт замыканию **ссылку на элемент**, а элементы здесь уже `&i32` — отсюда разыменование. Это место, где новички спотыкаются чаще всего; если компилятор ругается на типы в `filter`, попробуйте добавить или убрать `*`.

`enumerate` добавляет индекс, `skip` и `take` отрезают части:

```rust
for (i, val) in v.iter().enumerate().skip(4) {
    println!("{i} -> {val}");
}
// 4 -> 5
// 5 -> 6
```

`zip` склеивает два итератора в пары и останавливается на более коротком.

## Потребители

```rust
let sum: i32 = v.iter().sum();
let product: i32 = v.iter().take(3).product();
let count = v.iter().filter(|x| **x > 2).count();

println!("{:?}", v.iter().find(|x| **x > 3));   // Some(4)
println!("{}", v.iter().any(|x| *x > 5));       // true
println!("{}", v.iter().all(|x| *x > 0));       // true
```

`find` возвращает `Option` — первый подходящий элемент. `any` и `all` отвечают на вопросы о всей последовательности и **останавливаются досрочно**, как только ответ ясен.

Самый общий потребитель — `fold`: он несёт «накопитель» через всю последовательность:

```rust
let folded = v.iter().fold(0, |acc, x| acc + x * 2);   // 42
```

Первый аргумент — начальное значение, замыкание получает накопитель и элемент, возвращает новый накопитель. Через `fold` выражаются `sum`, `count` и почти всё остальное.

Отдельного слова заслуживает `collect` — он собирает итератор в коллекцию, но в **какую именно**, определяет тип:

```rust
let squares: Vec<i32> = v.iter().map(|x| x * x).collect();
let joined: String = words.iter().map(|w| w.to_uppercase())
    .collect::<Vec<_>>().join(", ");
```

Поэтому `collect` почти всегда требует аннотации типа — либо у переменной, либо через `::<>` (эту запись называют «турбофиш»). `_` внутри означает «тип элемента выведи сам».

## Реальный пример

Так выглядит типичная обработка данных:

```rust
let names: Vec<String> = users
    .iter()
    .filter(|u| u.age >= 18)
    .map(|u| u.name.clone())
    .collect();
```

Три строки читаются как формулировка задачи: взять пользователей, отобрать совершеннолетних, взять имена. Цикл с `if` и ручным `push` занял бы вдвое больше места и потребовал бы вчитываться.

При этом производительность не страдает. Итераторы в Rust — абстракция с нулевой стоимостью: компилятор разворачивает цепочку в такой же машинный код, какой получился бы из ручного цикла. Писать цикл ради скорости не нужно.

## Свой итератор

Достаточно реализовать `next`:

```rust
struct Counter { count: u32 }

impl Iterator for Counter {
    type Item = u32;

    fn next(&mut self) -> Option<u32> {
        if self.count < 5 {
            self.count += 1;
            Some(self.count)
        } else {
            None
        }
    }
}
```

И сразу становятся доступны все адаптеры и потребители:

```rust
let total: u32 = Counter::new()
    .zip(Counter::new().skip(1))
    .map(|(a, b)| a * b)
    .filter(|x| x % 3 == 0)
    .sum();                       // 18
```

Один метод — и ваш тип встроился во всю экосистему. Это хорошая иллюстрация того, зачем нужны трейты.

## Что запомнить

- `Iterator` требует один метод `next`, всё остальное строится поверх него.
- `.iter()` даёт ссылки, `.iter_mut()` — изменяемые ссылки, `.into_iter()` забирает владение.
- Итераторы ленивы: без потребителя не выполняется ничего.
- Адаптеры (`map`, `filter`, `take`, `zip`, `enumerate`) возвращают итератор; потребители (`collect`, `sum`, `fold`, `find`, `any`) запускают вычисление.
- `filter` получает ссылку на элемент — отсюда лишние звёздочки в замыканиях.
- `collect` требует указания целевого типа: аннотацией или турбофишем `::<Vec<_>>()`.
- Цепочки итераторов не медленнее ручных циклов.
- Свой итератор — это реализация `next`; все остальные методы появляются бесплатно.

## Практика

**1. Три вида итерации.** Для одного вектора строк вызовите `iter`, `iter_mut` и `into_iter`. Проверьте после каждого, доступен ли вектор. Готово, когда есть таблица «метод → тип элемента → судьба коллекции».

**2. Ленивость.** Напишите цепочку с `map`, печатающим элементы, но без потребителя. Убедитесь, что вывода нет, и прочитайте предупреждение. Добавьте `for_each` или `collect`. Готово, когда понимаете, что именно запускает вычисление.

**3. Цепочка вместо цикла.** Дан вектор чисел. Одной цепочкой получите сумму квадратов нечётных чисел, больших 10. Затем напишите то же обычным циклом и сравните читаемость. Готово, когда оба варианта дают одинаковый результат.

**4. Работа со структурами.** Дан вектор структур «товар» с полями «название», «цена», «в наличии». Одной цепочкой получите названия товаров в наличии дешевле 1000, отсортированные по цене. Готово, когда цепочка читается как формулировка задачи.

**5. Свой итератор.** Реализуйте `Fibonacci` — итератор чисел Фибоначчи. С помощью `take` возьмите первые 10, через `filter` оставьте чётные, посчитайте сумму. Готово, когда цепочка работает и вы не написали ни одного цикла.
