# 19. Замыкания: `Fn`, `FnMut`, `FnOnce`

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Замыкание — безымянная функция, которую можно сохранить в переменную и передать дальше. Главное отличие от обычной функции: замыкание **захватывает** переменные из окружения. А раз захватывает — значит, вступает в игру владение, и появляются три разных вида замыканий.

## Синтаксис

Параметры перечисляются между вертикальными чертами:

```rust
let add_one = |x| x + 1;
println!("{}", add_one(5));      // 6
```

Типы обычно не пишут: замыкание живёт рядом с местом использования, и компилятор выводит их из вызова. Полная форма с телом в фигурных скобках тоже возможна:

```rust
let add_one = |x: i32| -> i32 { x + 1 };
```

Есть тонкость: типы выводятся **один раз**. Вызвав замыкание со строкой, вы уже не сможете вызвать его с числом — тип зафиксировался при первом использовании.

## Три способа захвата

Замыкание берёт переменные из окружения тремя способами — ровно теми же, что и функции из статей 6–7.

**По неизменяемой ссылке** — если достаточно почитать:

```rust
let list = vec![1, 2, 3];
let only_borrows = || println!("список: {list:?}");
only_borrows();
println!("после: {list:?}");      // список по-прежнему доступен
```

**По изменяемой ссылке** — если замыкание что-то меняет:

```rust
let mut count = 0;
let mut inc = || {
    count += 1;
    println!("count={count}");
};
inc();
inc();
```

Само замыкание пришлось объявить с `mut`: оно хранит изменяемое заимствование, а значит, вызов его меняет.

**По значению** — с ключевым словом `move`:

```rust
let text = String::from("привет");
let consume = move || println!("забрал: {text}");
consume();
```

`move` заставляет замыкание забрать владение. После этого исходная переменная недоступна:

```
error[E0382]: borrow of moved value: `v`
  |
3 |     let c = move || println!("{v:?}");
  |             -------            - variable moved due to use in closure
  |             |
  |             value moved into closure here
```

Компилятор выбирает наименее ограничивающий способ сам; `move` нужен, когда замыкание переживает текущую область видимости — например, уезжает в другой поток (статья 24) или возвращается из функции.

## Три трейта

Способ захвата определяет, какие трейты замыкание реализует. Именно их указывают в сигнатурах функций:

| Трейт | Что делает с захваченным | Сколько раз вызывается |
|---|---|---|
| `FnOnce` | **поглощает** значения | один раз |
| `FnMut` | изменяет | много раз |
| `Fn` | только читает | много раз, в том числе одновременно |

Трейты вложены друг в друга: всякое `Fn` является и `FnMut`, и `FnOnce`. `FnOnce` реализуют **все** замыкания — вызвать хотя бы раз можно любое.

Посмотрим на `FnOnce` в чистом виде — замыкание, отдающее захваченное значение наружу:

```rust
// ❌ не компилируется
let text = String::from("привет");
let consume = move || text;
consume();
consume();
```

```
error[E0382]: use of moved value: `consume`
  |
4 |     consume();
  |     --------- `consume` moved due to this call
5 |     consume();
  |     ^^^^^^^ value used here after move
  |
note: closure cannot be invoked more than once because it moves the variable
      `text` out of its environment
```

Строку можно отдать только один раз — второго вызова не будет.

## Замыкание как параметр

Функция, принимающая замыкание, объявляет нужный трейт ограничением:

```rust
fn apply<F: Fn(i32) -> i32>(f: F, v: i32) -> i32 {
    f(v)
}

fn apply_mut<F: FnMut()>(mut f: F) {
    f();
    f();
}
```

Правило выбора: **требуйте самый слабый трейт из достаточных**. Нужен один вызов — `FnOnce`; нужно менять окружение — `FnMut`; хватает чтения — `Fn`. Чем слабее требование, тем больше замыканий подойдёт.

Именно так устроены методы стандартной библиотеки:

```rust
let mut v = vec![3, 1, 2];
v.sort_by_key(|x| -x);           // [3, 2, 1]
```

## Возврат замыкания

Каждое замыкание имеет собственный анонимный тип, поэтому назвать его в сигнатуре нельзя. Помогают знакомые приёмы из статьи 16:

```rust
fn make_adder(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x + n
}

fn make_boxed(n: i32) -> Box<dyn Fn(i32) -> i32> {
    Box::new(move |x| x * n)
}
```

`move` здесь обязателен: `n` — локальная переменная, и без захвата по значению возвращённое замыкание ссылалось бы на освобождённую память. Компилятор это, разумеется, не пропустит.

`impl Fn` предпочтительнее — без выделения памяти. `Box<dyn Fn>` нужен, когда из функции могут вернуться разные замыкания или их надо хранить в коллекции.

## Что запомнить

- Замыкание — безымянная функция с захватом окружения; типы параметров обычно выводятся, но фиксируются при первом использовании.
- Захват бывает по неизменяемой ссылке, по изменяемой ссылке и по значению (`move`).
- Компилятор выбирает наименее ограничивающий способ; `move` нужен, когда замыкание переживает текущую область.
- `Fn` только читает, `FnMut` изменяет, `FnOnce` поглощает и вызывается один раз.
- Трейты вложены: `Fn` ⊂ `FnMut` ⊂ `FnOnce`.
- В параметрах требуйте самый слабый подходящий трейт.
- Возвращают замыкания через `impl Fn` (дешевле) или `Box<dyn Fn>` (гибче).

## Практика

**1. Три захвата.** Напишите три замыкания над одним вектором: печатающее его, добавляющее элемент и забирающее владение. После каждого проверьте, доступен ли вектор снаружи. Готово, когда есть таблица «способ захвата → что стало с переменной».

**2. Счётчик.** Напишите замыкание, которое при каждом вызове увеличивает счётчик и печатает его. Вызовите пять раз. Готово, когда программа печатает от 1 до 5 и вы понимаете, зачем понадобился `mut`.

**3. `FnOnce` на практике.** Воспроизведите ошибку с двумя вызовами поглощающего замыкания. Затем измените его так, чтобы вызывать можно было многократно. Готово, когда понимаете, что именно делало его одноразовым.

**4. Замыкание как параметр.** Напишите функцию `repeat<F: FnMut(u32)>(times: u32, f: F)`, вызывающую замыкание с номерами итераций. Передайте в неё замыкание, накапливающее сумму. Готово, когда после вызова сумма доступна снаружи.

**5. Фабрика замыканий.** Напишите `make_multiplier(k: i32) -> impl Fn(i32) -> i32`. Создайте два умножителя с разными коэффициентами и примените к одному числу. Затем сложите оба в `Vec<Box<dyn Fn(i32) -> i32>>` и вызовите в цикле. Готово, когда работают оба варианта.
