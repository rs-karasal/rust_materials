# 1. Rust: зачем он нужен, установка и первая программа

Rust — компилируемый язык, который даёт скорость C++ и при этом на этапе компиляции отсекает целый класс ошибок работы с памятью. Звучит как маркетинг, но за этим стоит конкретный технический механизм, ради которого язык и стоит учить. В этой статье разберёмся, какую проблему решает Rust, поставим тулчейн и напишем первую программу — без Cargo, чтобы увидеть, что происходит на самом низком уровне.

## Какую проблему решает Rust

Исторически языки делились на два лагеря.

**Языки с ручным управлением памятью** — C, C++. Быстрые, дают полный контроль над железом, но программист сам отвечает за то, чтобы не обратиться к освобождённой памяти, не освободить один участок дважды и не выйти за границу массива. Человек ошибается, и цена ошибки — падение программы или уязвимость. По оценкам Microsoft и Google, около 70% критических уязвимостей в их больших C/C++ проектах связаны именно с памятью.

**Языки со сборщиком мусора** — Go, Java, Python, C#. Здесь память освобождает рантайм, программист про неё почти не думает. Платой становятся паузы сборщика, дополнительный расход памяти и невозможность использовать язык там, где рантайма просто нет: в ядре ОС, во встраиваемых системах, в WebAssembly-модулях.

Rust предлагает третий путь. Он не имеет сборщика мусора, но и не доверяет управление памятью человеку. Вместо этого компилятор **на этапе сборки доказывает**, что программа обращается с памятью корректно, — с помощью системы владения (ownership). Не доказал — программа не собирается.

Отсюда главное следствие для вас как для ученика: **компилятор Rust будет спорить с вами гораздо чаще, чем компиляторы других языков**. Это не придирки, а перенос отладки из продакшена на этап сборки. Первые недели это раздражает, потом начинает нравиться.

## Установка

Rust ставится одним инструментом — `rustup`. Это менеджер версий: он устанавливает компилятор, обновляет его и умеет держать несколько версий рядом.

На macOS и Linux:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

На Windows — скачайте `rustup-init.exe` с [rustup.rs](https://rustup.rs).

Установщик задаст пару вопросов, на все можно ответить по умолчанию. После установки перезапустите терминал и проверьте, что всё на месте:

```bash
rustc --version
cargo --version
```

Вывод будет примерно такой (номера версий у вас будут свежее):

```
rustc 1.93.0 (254b59607 2026-01-19)
cargo 1.93.0 (083ac5135 2025-12-15)
```

Что именно установилось:

- **`rustc`** — сам компилятор. Превращает исходный код в исполняемый файл. Напрямую вы будете вызывать его редко.
- **`cargo`** — сборщик и менеджер пакетов. Основной инструмент повседневной работы, ему посвящена следующая статья.
- **`rustup`** — менеджер тулчейна. Обновление всего Rust — это `rustup update`.

## Первая программа

Создайте файл `main.rs` и напишите в нём:

```rust
fn main() {
    println!("Привет, мир!");
}
```

Скомпилируйте и запустите:

```bash
rustc main.rs
./main
```

```
Привет, мир!
```

Рядом появился исполняемый файл `main` — самодостаточный бинарник, которому для запуска не нужен установленный Rust. Именно это отличает компилируемый язык от Python или JavaScript.

Разберём код по частям.

**`fn main()`** — объявление функции. `fn` от *function*. `main` — особенное имя: именно с этой функции начинается выполнение любой исполняемой программы на Rust. Пустые скобки означают, что параметров она не принимает.

**Фигурные скобки** ограничивают тело функции. Принятый стиль — открывающая скобка на той же строке, отступ в 4 пробела.

**`println!`** — вывод строки с переводом строки на конце. Обратите внимание на восклицательный знак: он означает, что перед вами не функция, а **макрос** (macro). Макрос разворачивается в код на этапе компиляции, поэтому умеет то, чего обычная функция не может, — например, принимать разное количество аргументов и проверять формат строки прямо при сборке. Пока достаточно запомнить правило: `!` в конце имени = макрос.

**Точка с запятой** завершает инструкцию. В Rust она значит больше, чем в других языках, — к этому вернёмся в статье про выражения.

## Компилятор — ваш главный учитель

Сломаем программу намеренно: уберём восклицательный знак.

```rust
// ❌ не компилируется
fn main() {
    println("Привет, мир!");
}
```

```
error[E0423]: expected function, found macro `println`
 --> bad.rs:2:5
  |
2 |     println("Привет, мир!");
  |     ^^^^^^^ not a function
  |
help: use `!` to invoke the macro
  |
2 |     println!("Привет, мир!");
  |            +

error: aborting due to 1 previous error

For more information about this error, try `rustc --explain E0423`.
```

Посмотрите, сколько здесь полезного. Компилятор назвал код ошибки, показал точное место, объяснил суть («не функция») и **предложил готовое исправление** с указанием, куда вставить символ. А команда `rustc --explain E0423` выдаст развёрнутую статью с примерами.

Заведите привычку с самого начала: **читать сообщение целиком, а не только первую строку**. Диагностика — сильнейшая сторона Rust, и она заменит вам половину учебников.

## Что запомнить

- Rust даёт безопасность работы с памятью без сборщика мусора: корректность проверяет компилятор на этапе сборки.
- Цена — более строгий компилятор. Он спорит не из вредности, а вместо будущей отладки.
- `rustup` управляет версиями, `rustc` компилирует, `cargo` собирает проекты.
- Точка входа в программу — функция `main`.
- Восклицательный знак в конце имени (`println!`) означает макрос, а не функцию.
- Результат компиляции — самодостаточный бинарник, которому Rust на машине не нужен.
- Сообщения об ошибках содержат код (`E0423`), точное место и часто готовое исправление. `rustc --explain <код>` даёт подробности.

## Практика

**1. Проверка окружения.** Установите Rust и выведите версии всех трёх инструментов: `rustc`, `cargo`, `rustup`. Готово, когда все три команды отрабатывают без ошибок.

**2. Своё приветствие.** Измените программу так, чтобы она выводила три строки: приветствие с вашим именем, текущий год и название языка. Используйте три отдельных вызова `println!`. Готово, когда программа печатает ровно три строки.

**3. Коллекция ошибок.** Сломайте программу тремя разными способами: уберите точку с запятой в середине блока из нескольких инструкций, напишите `fn Main()` с большой буквы, забудьте закрывающую кавычку. Для каждого случая запишите код ошибки и первую строку сообщения. Готово, когда у вас есть табличка из трёх строк «что сломал → что ответил компилятор».

**4. Разбор незнакомой ошибки.** Возьмите любой код ошибки из предыдущей задачи и выполните `rustc --explain <код>`. Прочитайте объяснение. Готово, когда можете своими словами сказать, какое правило языка нарушено.

**5. Ищем в документации.** Выполните `rustup doc --std`, найдите макрос `print!` (без `ln`). Чем он отличается от `println!`? Напишите программу, которая с помощью `print!` выводит слова `Привет`, `мир` и `!` тремя отдельными вызовами, но в одну строку. Готово, когда вывод визуально не отличается от исходной программы.

## Вопросы для самопроверки

1. Чем подход Rust к управлению памятью отличается от подхода C++ и от подхода Go? Что Rust выигрывает и чем платит?
2. Почему `println!` пишется с восклицательным знаком, а `main` — нет?
3. За что отвечает `rustup`, а за что `rustc`? Зачем нужны оба инструмента?
4. Что произойдёт, если переименовать функцию `main` в `start` и попытаться собрать программу?
5. Почему собранный бинарник запускается на машине, где Rust не установлен, а скрипт на Python без интерпретатора — нет?
6. Что означает запись `error[E0423]` и как получить по ней подробное объяснение, не открывая браузер?
