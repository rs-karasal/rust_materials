# 11. Модули, `pub` и разделение кода на файлы

> ⏱ **~45 минут** · теория 20 мин · практика 25 мин

Пока весь код помещался в `main.rs`. В реальном проекте так не бывает: файлов десятки, и нужен способ их организовать, а заодно решить, какие детали видны снаружи, а какие спрятаны. В Rust за это отвечает система модулей.

## Три уровня организации

Терминология поначалу путает, но она простая:

- **Крейт** (crate) — единица компиляции. Бывает двух видов: *исполняемый* (точка входа `src/main.rs`) и *библиотечный* (`src/lib.rs`, точки входа нет, но код можно использовать в других проектах).
- **Пакет** (package) — то, что описано одним `Cargo.toml`. Содержит один библиотечный крейт и/или сколько угодно исполняемых.
- **Модуль** (module) — раздел внутри крейта. Модули образуют дерево и управляют видимостью.

Проект из статьи 2 — это пакет с одним исполняемым крейтом.

## Модули и приватность

Модуль объявляется словом `mod`:

```rust
mod outer {
    fn hidden() {}
}

fn main() {
    outer::hidden();
}
```

```
error[E0603]: function `hidden` is private
 --> src/main.rs:4:20
  |
4 | fn main() { outer::hidden(); }
  |                    ^^^^^^ private function
```

Вот главное правило: **всё в модуле приватно по умолчанию**. Не только функции — структуры, их поля, перечисления, вложенные модули.

Логика та же, что у неизменяемости из статьи 3: закрыто, пока вы явно не откроете. Модуль получает право менять свои внутренности, не ломая чужой код, — снаружи видно только то, что вы сознательно объявили частью интерфейса.

Открывает доступ ключевое слово `pub`:

```rust
mod outer {
    pub fn visible() {}
}
```

Видимость работает в одну сторону: **вложенный модуль видит всё в родительском**, даже приватное, а родитель во вложенном — только `pub`. Детали доступны изнутри, но не снаружи.

Отдельная тонкость: `pub struct` не делает публичными свои поля. Каждое поле открывают отдельно:

```rust
pub struct Asparagus {
    pub height: u32,      // видно снаружи
    variety: String,      // скрыто
}
```

Это позволяет отдавать структуру наружу, оставляя часть данных под контролем своих методов. А вот `pub enum` открывает все варианты сразу — перечисление без вариантов бессмысленно.

## Пути и `use`

Обратиться к элементу можно двумя видами путей:

- **абсолютный** — от корня крейта: `crate::garden::vegetables::Asparagus`;
- **относительный** — от текущего модуля: `garden::vegetables::Asparagus`, `self::helper`, `super::parent_fn`.

`super` означает «на уровень выше» — как `..` в файловой системе. Удобно, когда вложенный модуль зовёт функцию родителя.

Писать длинные пути каждый раз утомительно, поэтому их сокращают через `use`:

```rust
use garden::vegetables::Asparagus;

fn main() {
    let plant = Asparagus::new();
}
```

Соглашение: для **функций** импортируют родительский модуль (`use crate::garden::vegetables;` и потом `vegetables::count()`), а для **типов** — сам тип. Так в месте вызова видно, откуда взялась функция, а имена типов не удлиняются зря.

Если два импортируемых имени совпадают, помогает `as`:

```rust
use std::fmt::Result;
use std::io::Result as IoResult;
```

Несколько элементов из одного места объединяют в фигурные скобки: `use std::{cmp::Ordering, io};`

## Разделение на файлы

Теперь самое практичное. Объявление `mod garden;` **с точкой с запятой вместо тела** говорит компилятору: «содержимое модуля лежит в отдельном файле».

Проект из трёх файлов:

```
src/
├── main.rs
├── garden.rs
└── garden/
    └── vegetables.rs
```

`src/main.rs`:

```rust
mod garden;

use garden::vegetables::Asparagus;

fn main() {
    let plant = Asparagus::new();
    println!("{plant:?}");
}
```

`src/garden.rs`:

```rust
pub mod vegetables;
```

`src/garden/vegetables.rs`:

```rust
#[derive(Debug)]
pub struct Asparagus {
    pub height: u32,
    variety: String,
}

impl Asparagus {
    pub fn new() -> Self {
        Self { height: 10, variety: String::from("обычная") }
    }
}
```

Правило простое: **имя файла = имя модуля, подмодули — в одноимённой папке**. Компилятор не сканирует папки сам: пока модуль не объявлен через `mod`, его файл — просто мёртвый текст на диске. Это частая причина недоумения новичков: файл создан, а компилятор его «не видит».

Есть и старый стиль — `garden/mod.rs` вместо `garden.rs`. Он до сих пор поддерживается и встречается в старых проектах, но в новом коде пользуйтесь первым вариантом: иначе в редакторе открыто пять вкладок с именем `mod.rs`.

## Реэкспорт

Иногда удобная структура файлов неудобна для пользователя библиотеки. Тогда путь «поднимают» через `pub use`:

```rust
pub use crate::garden::vegetables::Asparagus;
```

Теперь снаружи тип доступен как `my_crate::Asparagus`, хотя внутри лежит глубже. Так библиотеки прячут свою внутреннюю структуру за коротким удобным интерфейсом.

## Что запомнить

- Крейт — единица компиляции (`main.rs` или `lib.rs`), пакет — то, что описано одним `Cargo.toml`, модуль — раздел внутри крейта.
- Всё приватно по умолчанию; `pub` открывает доступ.
- Вложенный модуль видит родительский целиком, родитель вложенный — только `pub`-элементы.
- `pub struct` не делает поля публичными, каждое поле открывается отдельно; `pub enum` открывает все варианты.
- Пути бывают абсолютные (`crate::...`) и относительные (`self`, `super`); `use` сокращает их.
- Соглашение: импортируют модуль для функций и сам тип для типов.
- `mod name;` подключает файл `name.rs`; подмодули лежат в папке `name/`. Без объявления `mod` файл не компилируется вообще.
- `pub use` переэкспортирует элемент, скрывая внутреннюю структуру крейта.

## Практика

**1. Первый модуль.** В одном файле объявите модуль `math` с публичной функцией `square` и приватной `helper`. Вызовите обе из `main` и убедитесь, что вторая недоступна. Готово, когда получили `E0603` и понимаете сообщение.

**2. Вынос в файл.** Перенесите модуль `math` в `src/math.rs`, не меняя код `main`. Готово, когда программа собирается, а в `main.rs` осталась одна строка объявления модуля.

**3. Вложенность.** Добавьте подмодуль `math::geometry` в файле `src/math/geometry.rs` с функцией площади круга. Вызовите её из `main` абсолютным путём, затем сократите через `use`. Готово, когда работают оба варианта.

**4. Забытый `mod`.** Создайте файл `src/unused.rs` с любой функцией, но **не** объявляйте модуль. Попробуйте вызвать функцию и объясните ошибку. Готово, когда можете сказать, почему компилятор не нашёл файл.

**5. Приватные поля.** Опишите в модуле структуру `Account` с публичным полем `owner` и приватным `balance`, плюс публичный метод для чтения баланса. Из `main` попробуйте изменить баланс напрямую. Готово, когда прямое обращение отклонено, а через метод значение доступно.
